# Charts and data

- Use a real chart library, not hand-drawn SVG.
- Offer chart types that fit the data. Show more data across time with colors and categories.
- Every chart must say something. Drop charts that do not.
- Show the actual value, not only the difference. Get units and suffixes right.
- Lead with key numbers that are not already shown elsewhere on the dashboard.
- Use a variety of chart types in data views. (A varied set of charts gives a clearer picture of the data.)
- Use a real chart library for data charts, not hand-drawn SVG shapes. (Hand-drawn charts had odd shapes and unclear markers.)
- Make every chart show a clear takeaway. Remove charts that show no useful pattern. (A line chart with no clear meaning added noise rather than insight.)
- Never add decorative shapes that look like data bars or controls. (Unlabeled blue bars looked like data or a clickable element, which confused users.)
- Show a few totals as plain large numbers instead of a chart. (A chart for a couple of numbers adds space and text without helping interpretation.)
- Place data labels so they do not distort the visual height of bars. (Labels placed outside bars can make a value look less than double another.)
- Limit multi-series bar charts, because more series make each one harder to read. (Too many series hide the insight.)
- Order bar categories so the comparison the audience needs is easiest to make. (Bar spacing groups bars, so category order changes how they read.)
- Use a slopegraph to compare two points across categories, and a waterfall chart to show a start, changes, and an end. (Each chart type fits a specific comparison.)
- Show in the table below a chart the same data columns that the chart shows. (A table that is missing columns does not match the chart above it.)
- Bind chart colors to theme tokens so they switch when the theme changes. (Chart colors did not update when the theme changed.)
