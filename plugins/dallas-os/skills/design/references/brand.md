# Brand

- Use the brand kit's fonts, logo, and colors in every output. Never fall back to generic or serif fonts.
- Give each site one ownable visual element, so it does not look like every other site in its field.
- Use references as inspiration. Never copy a reference site.
- Give brand graphics like grids a meaning. No pure decoration.
- Add depth and contrast to flat designs (for example dark headers), but keep the data the focus.
- Show the logo once per view, at a modest size.
- Add subtle brand marks in places like sheet corners or the bottom of a sidebar.
- Match tone, music, and imagery to the real audience.
- When a client product should feel like its own brand, do not make it look like RoleModel. Try other UI fonts.
- Go-to marketing site direction: dark nav, subtle grid lines, small logo.
- Favor off-white backgrounds with subtle solid grid lines (not dots) for boards and canvases.
- List every component in the brand guide. (The brand guide should show the full component set.)
- Use one shared style source for the brand kit and previews, so colors and shadows always match. (Colors and shadows drifted between the brand kit and the review preview.)
- Present brand merge options as a written comparison on its own page, protected by the same password as the review. (Merge writeups are a separate deliverable that clients access the same way as the review.)
- Add a new logo to a brand without overwriting the logos it already has. (Adding a board logo should not replace the current brand logo.)
- Show the theme color swatches in the component kit. (The theme colors are visible at a glance.)
- Pull default ad text styles from the brand context. (Ads should match the brand without manual setup.)
- Build every site from components in the brand kit so they appear on every view. (Site pages were not showing the brand kit components they should use.)
